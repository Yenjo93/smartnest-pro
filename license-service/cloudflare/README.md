# خدمة ترخيص SmartNest على Cloudflare

هذه نسخة Cloudflare Workers من الخدمة، مع قاعدة بيانات D1. لا تحتاج سيرفر Docker. إعداد النشر مخصص لحساب Cloudflare الذي يدير `smartnest.pro`، وللعنوان `https://licenses.smartnest.pro`.

واجهة التحقق مطابقة للخدمة الأصلية، لذلك إضافة Home Assistant تستعملها بدون تعديل البروتوكول. يمكن أيضًا استعمال أوامر الإدارة الموجودة في `../server.py` بعد ضبط `SMARTNEST_SERVICE_URL=https://licenses.smartnest.pro` وسر الإدارة في البيئة.

خدمة الإنتاج منشورة على `https://licenses.smartnest.pro` وقاعدة D1 مجهزة. نجح اختبار HTTPS وإصدار مفتاح مؤقت وتفعيله ورفض تثبيت ثانٍ وإيقافه؛ المفتاح التجريبي موقوف. لم يتم اختبار إضافة Home Assistant على جهاز فعلي بعد.

## أوامر النشر

من هذا المجلد، مع Node.js متوافق مع `engines` في `package.json`:

```sh
npm ci
npx cf auth login
npm test
npm run check
npm run deploy -- --secrets-file ../.owner-secrets.json
```

`cloudflare.config.ts` يحتوي ربط قاعدة البيانات والعنوان وحدود الطلبات والسجلات. ملف `.owner-secrets.json` خاص بصاحب الخدمة، موجود محليًا فقط ومُستثنى من Git. احتفظ بنسخة آمنة منه بمدير كلمات مرور؛ من يفقده يستطيع استبدال سر الإدارة من حساب Cloudflare، لكن لا ينشر السر ولا يعطيه للزبائن. عند استنساخ المشروع لحساب آخر، أنشئ قاعدة جديدة وعدّل رقمها والدومين قبل النشر.

لتنفيذ أوامر الإدارة من جهاز المالك، يستخدم `python3 license-service/manage.py` ملف السر الخاص تلقائيًا؛ مثل `python3 license-service/manage.py create --days 365` أو `list` أو `revoke LICENSE_UUID`. لا تنفذ أمر `serve` عبر هذا المساعد؛ هو مخصص لإدارة الخدمة المنشورة.

## التجهيز الأول

1. أنشئ قاعدة D1 باسم `smartnest-licenses`، ونفّذ محتوى `schema.sql` مرة واحدة من وحدة SQL الخاصة بقاعدة البيانات. احتفظ بنسخ احتياطية ولا تحذف القاعدة عند تحديث الكود.
2. أنشئ Worker باسم `smartnest-licenses` وانشر `worker.mjs`. إعداد أداة Cloudflare CLI موجود في `cloudflare.config.ts`؛ لا حاجة لتشغيل خدمة Python هنا.
3. أضف ربط D1 باسم **`DB`** يشير إلى القاعدة.
4. أضف **Secret** باسم **`SMARTNEST_ADMIN_TOKEN`** بقيمة عشوائية قوية لا تقل عن ٣٢ حرفًا. خزّنها بمدير كلمات مرور؛ لا تضعها في GitHub، ولا ترسلها للزبائن. توليد قيمة ممكن بـ `python3 -c 'import secrets; print(secrets.token_urlsafe(48))'` في جهازك.
5. أضف ربط **Rate Limiting** باسم **`RATE_LIMITER`** من إعداد النشر، بحد ٦٠ طلبًا خلال ٦٠ ثانية. يستخدم الكود مفتاحًا منفصلًا لطلبات التفعيل والإدارة لكل عنوان IP. الحدود تقريبية ومستقلة بين مراكز Cloudflare؛ ليست بديلًا عن قواعد مكافحة الإساءة في حسابك.
6. اربط Worker بنطاق مخصص **`licenses.smartnest.pro`** وتأكد من HTTPS. اربط النطاق الأساسي `smartnest.pro` بالموقع العام الموصوف أدناه ولا النطاقات الفرعية الأخرى.
7. فعّل السجلات والتتبّع في إعداد النشر دون تسجيل أجسام الطلبات أو ترويسات Authorization.
8. من جذر مستودع SmartNest شغّل `python3 scripts/configure-license-service.py https://licenses.smartnest.pro`، ثم وزّع الإضافة المحدثة وأعد تشغيل Home Assistant. الزبون يدخل مفتاحه فقط.

الخدمة ترفض التفعيل والإدارة إذا كان ربط قاعدة البيانات أو ربط الحدود أو سر الإدارة مفقودًا. أبق واجهة الإدارة محمية بالسر؛ يفضّل أيضًا تقييدها بعنوانك أو شبكة موثوقة، مع السماح لواجهة `/v1/validate` بالوصول العام. عند إضافة حماية خارجية، عدّل عميل الإدارة بما يناسبها.

## إصدار المفاتيح

من مجلد `license-service`، مع إعداد `SMARTNEST_ADMIN_TOKEN` و`SMARTNEST_SERVICE_URL` في بيئتك الخاصة:

```sh
python3 server.py create --days 365
python3 server.py create
python3 server.py list
python3 server.py revoke LICENSE_UUID
python3 server.py reset LICENSE_UUID
```

المفتاح الكامل يظهر مرة واحدة عند الإصدار. خزّنه وارسله للزبون بشكل خاص؛ القائمة وقاعدة البيانات لا تحتويانه كنص واضح. بدون `--days` يكون الترخيص دائمًا. إعادة ربط تثبيت بديل عبر `reset` لا تلغي الإيقاف. الإيقاف يصل عند التحقق الدوري التالي؛ أثناء انقطاع الإنترنت تبقى مهلة التفعيل المحفوظة حتى ٧٢ ساعة، دون تجاوز نهاية الترخيص.

## الاختبارات المحلية

```sh
cd license-service/cloudflare
npm test
```

تحتاج Node.js 24 الذي يوفر `node:sqlite`. الاختبارات تشغّل كود Worker الحقيقي مع قاعدة SQLite محلية بديلة لواجهة D1. هذا يختبر البروتوكول وSQL والحماية؛ يلزم أيضًا تجربة Worker المنشور مع D1 الفعلي قبل دمج الإصدار وتوزيعه.


## صفحة إدارة التراخيص

افتح `https://licenses.smartnest.pro/admin`. كلمة الدخول مستقلة عن سر واجهة الإدارة، ومحفوظة لمالك هذا الجهاز في `license-service/.admin-access.txt`؛ الملف خاص ومستثنى من Git. جلسة الدخول تستمر ٨ ساعات، بكوكي آمنة لا يقرأها JavaScript. تسجيل الخروج يمسح كوكي هذا المتصفح. تغيير كلمة مرور اللوحة من سر `SMARTNEST_PANEL_PASSWORD` في Cloudflare يبطل الجلسات السابقة؛ حفظها محليًا في `.owner-secrets.json` ضروري حتى لا تعيد عمليات النشر السر القديم.

اختر ٣ شهور أو ٦ شهور أو سنة أو مدى الحياة ثم اضغط إصدار مفتاح. المدة تبدأ وقت الإصدار وتحسب بالشهور الميلادية، مع ضبط آخر يوم من الشهر. المفتاح يظهر مرة واحدة؛ انسخه أو نزّله قبل إخفائه. القائمة تعرض رقم الترخيص وحالته وتاريخ انتهائه؛ زر إيقاف يطلب تأكيدًا قبل التنفيذ. لا تشارك كلمة مرور الإدارة مع الزبائن؛ أعطهم مفتاح الترخيص فقط.

واجهة إنشاء المفاتيح تدعم `{ "plan": "3_months" }` أو `6_months` أو `1_year` أو `lifetime`؛ دعم `expires_at` لعميل الأوامر القديم باقٍ. لا يجوز إرسال الخطة والتاريخ معًا. لم تتغير واجهة التفعيل ولا قاعدة البيانات.


## اسم الزبون مع الترخيص

صفحة الإدارة تطلب اسم الزبون (١–١٠٠ حرف) عند إنشاء المفتاح، وتعرضه في القائمة وملف التنزيل. البحث يعمل بالاسم أو رقم الترخيص. الأسماء محمية بتسجيل دخول المالك ولا ترسلها واجهة تفعيل Home Assistant.

قبل تحديث Worker على قاعدة موجودة، نفّذ `migrations/0002-license-name.sql` **مرة واحدة فقط**. التغيير يضيف عمودًا بقيمة فارغة للتراخيص القديمة دون تعديل مفاتيحها أو تفعيلها أو صلاحيتها؛ تظهر القديمة باسم «بدون اسم». قواعد البيانات الجديدة تستعمل `schema.sql` الذي يحتوي العمود أصلًا، ولا تحتاج هذا الترحيل.

واجهة إنشاء المفتاح تقبل `customer_name`، مثل `{ "plan": "3_months", "customer_name": "أحمد" }`. عميل الأوامر يدعم `python3 license-service/manage.py create --days 90 --name "أحمد"`. ترك الاسم خارج طلب API القديم ما زال مدعومًا؛ الاسم المرسل صراحة لا يجوز أن يكون فارغًا أو أطول من ١٠٠ حرف.

## التجديد وملاحظات الزبون

صفحة الإدارة تدعم تجديد الترخيص بالمفتاح نفسه، وتعديل الاسم ووسيلة التواصل والملاحظات الخاصة. التجديد يضيف المدة إلى نهاية الترخيص الحالي أو إلى الوقت الحالي إذا انتهى، مع ضبط نهاية الشهر؛ لا يعيد تشغيل مفتاح موقوف ولا يقصّر ترخيص مدى الحياة. لا يُرسل رقم التواصل أو الملاحظات إلى العميل عند التفعيل، ولا يدخلان ملف المفتاح المُسلّم للزبون.

قبل نشر هذه النسخة على قاعدة قديمة، طبّق `migrations/0003-customer-notes.sql` **مرة واحدة** لإضافة عمودي `customer_contact` و`notes`. القواعد الجديدة المنشأة من `schema.sql` تحتويهما بالفعل؛ لا تطبّق الترحيل مرة أخرى عليها.

واجهات الإدارة الإضافية (بنفس حماية الجلسة أو رمز المالك):

- `POST /v1/admin/licenses/UUID/update` مع `customer_name` أو `customer_contact` أو `notes` لتحديث الحقول المرسلة فقط. التواصل حتى ١٢٠ حرفًا والملاحظات حتى ١٠٠٠ حرف.
- `POST /v1/admin/licenses/UUID/renew` مع `{"plan":"3_months"}` أو `6_months` أو `1_year` أو `lifetime`. التجديد المتزامن محمي من فقدان التعديلات. لا يرجع مفتاحًا جديدًا.

بطاقات التنبيه والفلاتر تعرض التراخيص التي تنتهي خلال ٧ أو ٣٠ يومًا، مع فلتر للمنتهية وبحث بالاسم أو الرقم أو وسيلة التواصل. هذه تذكيرات داخل اللوحة، ولا تُرسل رسائل خارجية تلقائيًا.

التحقق الناجح من المفتاح وتثبيته يعيد اسم صاحب الترخيص لعرضه في صفحة «ترخيصي» داخل نفس البيت. بيانات التواصل والملاحظات تبقى في واجهة المالك فقط ولا تظهر في رد التفعيل.


## موقع الزبائن والطلبات

الموقع العام على `https://smartnest.pro`، وصفحاته `/license` لطلب ترخيص، `/renew` للتجديد، `/support` للدعم، `/patreon`، و`/privacy`. يستخدم الشعار والخطوط المحلية من `public/brand` دون خدمات تتبع خارجية.

قبل النشر على قاعدة موجودة، طبّق `migrations/0004-public-requests.sql` لإضافة جدول الطلبات وإعداد الموقع. الترحيل قابل لإعادة التنفيذ ولا يعدّل التراخيص. يتطلب الموقع ربط `ASSETS` وحد طلبات `PUBLIC_REQUEST_LIMITER` الموجودين في إعداد Cloudflare.

كل طلب يحتفظ بالاسم ووسيلة التواصل والنوع والمدة والتفاصيل داخل D1، ويعيد للزائر رقمًا مرجعيًا فقط. لا توجد صفحة عامة لاستعراض الطلبات. تمنع الخدمة مفاتيح التفعيل الكاملة، وتحد حجم الطلب ومعدل الإرسال، وتمنع تكرار الطلب نفسه عند إعادة المحاولة. لا يصدر النموذج مفتاحًا، ولا يجدد أو يقبض أموالًا تلقائيًا.

داخل لوحة المالك، افتح «الطلبات» للبحث وفلترة الجديد وقيد المتابعة والمغلق، وكتابة ملاحظات داخلية. إجراء الإصدار يملأ بيانات الزبون لتراجعها قبل إصدار المفتاح؛ إجراء التجديد يساعدك على البحث عن ترخيصه، ويتطلب تجديده يدويًا. تواصل مع الزبون عبر الوسيلة التي اختارها؛ الموقع لا يرسل بريدًا أو واتساب تلقائيًا. احتفظ ببيانات التواصل فقط للمتابعة المطلوبة.

صفحة Patreon تعرض «قريبًا» مع نموذج اهتمام حتى تضيف رابط Patreon الرسمي من «إعدادات الموقع» في لوحة المالك. ترك الرابط فارغًا يعيد حالة «قريبًا». تقبل الخدمة روابط HTTPS الرسمية على patreon.com فقط؛ لا توجد أسعار أو روابط دفع افتراضية.


## العرض الحالي: سنة بـ35 USD وتجربة مجانية

الموقع يعرض خيارين لطلب جديد: `trial_month` لشهر تجربة تقويمي مجاني، أو `1_year` لسنة بـ35 دولار أمريكي. التجديد العام سنوي فقط. أزيلت عروض ٣ و٦ شهور ومدى الحياة من نماذج الموقع والإصدار؛ سجلات التراخيص القديمة وواجهات المالك المتوافقة باقية دون تغيير صلاحيتها.

لوحة المالك تستطيع إصدار شهر التجربة، ويُحسب تاريخ انتهائه على الخادم مع ضبط نهاية الشهر. راجع التجارب السابقة يدويًا قبل الإصدار؛ لا يوجد إصدار مجاني تلقائي. التجربة لا تتحوّل تلقائيًا لاشتراك مدفوع. تحقق من دفع Patreon قبل إصدار أو تجديد السنة. لا توجد مزامنة دفع أو webhook، ورابط الدفع يبقى قيد التجهيز حتى يحفظ المالك صفحة Patreon الرسمية في الإعدادات.
